# Fixture process ownership

`serverAgentFixture.js` is test infrastructure. Production Agent code is unchanged.

Only `VERIFIED_OWNED` can reach the injected signal sender. A positive decision requires an OS-observed PID, canonical full runtime/file identity, lossless argv pointing to the exact CLI and `run`, one exact fixture root, an OS start generation inside the fixture lifetime, the generation recorded at spawn, and a second identical inspection immediately before signaling. Markers only add candidates. They never authorize a signal or prove discovery complete.

Outcomes distinguish `VERIFIED_NOT_OWNED`, `VERIFIED_EXITED`, `QUERY_DENIED`, `QUERY_FAILED`, `IDENTITY_INCOMPLETE`, `PID_REUSED` and `DISCOVERY_INCOMPLETE`. Missing metadata is not exit evidence. OS errors, failed discovery and unresolved cleanup throw after saving diagnostics; they cannot produce `CLEANUP_PASS`.

All Agent-launching invocations must use `cleanup.spawn()`. It registers direct `run` children and installs a fixture-scoped preload before `ensure` imports production code. The preload records a spawn intent before each detached `run`, then the PID and initial OS inspection, before any lock/ready marker is needed. Cleanup seals launching, waits at most five seconds for tracked launchers to close, checks every journal intent/outcome, preflights all candidates, terminates only verified owners, and independently verifies exit. After a verified signal, an OS existence probe confirms exit without depending on teardown-time CIM identity fields; permission/query errors still fail. A complete stable OS observation with a strictly newer start generation proves only the registered original generation exited. The replacement PID remains live and receives no signal; the timeline retains PID_REUSED and the original/replacement generations. Unknown, partial, denied or racing observations cannot establish that proof. Failed writes/queries deliberately leave an unresolved fixture rather than risk signaling another process. Do not delete its evidence or bypass the verifier.

Windows uses PID-filtered CIM through the absolute system PowerShell path and the Node/CRT command-line rules. Full canonical paths plus filesystem device/inode identity handle case and symlinks. Darwin uses the existing `koffi` dependency, `libproc` (`proc_pidpath`, `PROC_PIDTBSDINFO`) and `libSystem` (`KERN_PROCARGS2`); microsecond epoch start values avoid locale/timezone/second-resolution `ps lstart` ambiguity. Linux uses NUL `/proc/PID/cmdline`, `/proc/PID/exe`, bracketed `/proc/PID/stat` start ticks and a `CLOCK_BOOTTIME` fixture boundary at `CLK_TCK` precision. A start tick overlapping that boundary is refused. Native Darwin and Linux behavior requires independent runtime validation.

## Linux exit state and reaping

Linux stat decoding returns the PID-checked state, PPID and start ticks. Ownership inspection reads stat before and after executable/NUL argv; a transition to Z needs one additional confirming Z stat. Only equal generations with two explicit Z observations produce LINUX_ZOMBIE. Matching a complete journal registration yields REGISTERED_GENERATION_ZOMBIE, never VERIFIED_OWNED or VERIFIED_EXITED. A missing executable alone proves neither death nor Zombie. Permission denial remains fail-closed. Evidence records stat state/ticks/PPID, exe/cmdline read status and existence-probe classification without dumping argv in failure diagnostics.

Linux exit observation is independent of full live identity and cannot authorize signals. Equal-generation Zombie means RUNTIME_TERMINATED=true and PID_REAPED=false. Cleanup waits within the existing 5000 ms exit budget, using a monotonic clock. Persistent Z fails and preserves process-cleanup.json; it never becomes CLEANUP_PASS. Affirmative ESRCH proves observed PID absence. A stable strictly newer start generation proves only the registered original ended and was reaped; the replacement may be live or Zombie and receives no signal. Partial/denied/older/racing observations cannot prove reaping. Tick generations are namespace/boot-local; registration and inspection must stay in the same PID namespace and boot. This does not supply an atomic kernel process handle.

The shared pending-reap cleanup path also requires targeted Mac runtime regression. Windows and Darwin inspectors and their native identity rules remain unchanged; Windows mocks of /proc are LINUX_MOCK_CONTRACT_PASS, not Linux runtime acceptance. Run both agentOwnershipSafety.test.js and linuxExitState.test.js before native lifecycle tests.

Linux references: [stat](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html), [kill zero](https://man7.org/linux/man-pages/man2/kill.2.html), [wait/reaping](https://man7.org/linux/man-pages/man2/waitpid.2.html), [cmdline](https://man7.org/linux/man-pages/man5/proc_pid_cmdline.5.html), [exe](https://man7.org/linux/man-pages/man5/proc_pid_exe.5.html), [PID namespaces and proc mounts](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html), [Linux 4.18 stat implementation](https://github.com/torvalds/linux/blob/v4.18/fs/proc/array.c). No pidfd dependency or production change is introduced.

A Zombie thread-group leader can coexist with surviving worker threads (e.g. pthread_exit). Runtime termination additionally requires stat field 20 num_threads=1 on both confirming Z observations. Z with multiple or unknown threads fails closed; it cannot prove that the entire Agent stopped executing. See [Linux 4.18 do_task_stat](https://github.com/torvalds/linux/blob/v4.18/fs/proc/array.c) and [pthread_exit](https://man7.org/linux/man-pages/man3/pthread_exit.3.html).
