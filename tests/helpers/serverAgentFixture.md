# Fixture process ownership

`serverAgentFixture.js` is test infrastructure. Production Agent code is unchanged.

Only `VERIFIED_OWNED` can reach the injected signal sender. A positive decision requires an OS-observed PID, canonical full runtime/file identity, lossless argv pointing to the exact CLI and `run`, one exact fixture root, an OS start generation inside the fixture lifetime, the generation recorded at spawn, and a second identical inspection immediately before signaling. Markers only add candidates. They never authorize a signal or prove discovery complete.

Outcomes distinguish `VERIFIED_NOT_OWNED`, `VERIFIED_EXITED`, `QUERY_DENIED`, `QUERY_FAILED`, `IDENTITY_INCOMPLETE`, `PID_REUSED` and `DISCOVERY_INCOMPLETE`. Missing metadata is not exit evidence. OS errors, failed discovery and unresolved cleanup throw after saving diagnostics; they cannot produce `CLEANUP_PASS`.

All Agent-launching invocations must use `cleanup.spawn()`. It registers direct `run` children and installs a fixture-scoped preload before `ensure` imports production code. The preload records a spawn intent before each detached `run`, then the PID and initial OS inspection, before any lock/ready marker is needed. Cleanup seals launching, waits at most five seconds for tracked launchers to close, checks every journal intent/outcome, preflights all candidates, terminates only verified owners, and independently verifies exit. After a verified signal, an OS existence probe confirms exit without depending on teardown-time CIM identity fields; permission/query errors still fail. A complete stable OS observation with a strictly newer start generation proves only the registered original generation exited. The replacement PID remains live and receives no signal; the timeline retains PID_REUSED and the original/replacement generations. Unknown, partial, denied or racing observations cannot establish that proof. Failed writes/queries deliberately leave an unresolved fixture rather than risk signaling another process. Do not delete its evidence or bypass the verifier.

Windows uses PID-filtered CIM through the absolute system PowerShell path and the Node/CRT command-line rules. Full canonical paths plus filesystem device/inode identity handle case and symlinks. Darwin uses the existing `koffi` dependency, `libproc` (`proc_pidpath`, `PROC_PIDTBSDINFO`) and `libSystem` (`KERN_PROCARGS2`); microsecond epoch start values avoid locale/timezone/second-resolution `ps lstart` ambiguity. Linux uses NUL `/proc/PID/cmdline`, `/proc/PID/exe`, bracketed `/proc/PID/stat` start ticks and a `CLOCK_BOOTTIME` fixture boundary at `CLK_TCK` precision. A start tick overlapping that boundary is refused. Native Darwin and Linux behavior requires independent runtime validation.

## Mac retest order

1. M2: `node --test tests/server-agent/agentOwnershipSafety.test.js`. All unsafe cases must leave the injected signal sender uncalled. This command uses synthetic process metadata and does not launch detached Agents.
2. M2.5: Before any detached test, run a read-only self query through `createProcessInspector()(process.pid)`. Confirm `OBSERVED`, the full executable, exact argv boundaries and a valid microsecond generation. Check those fields against the known self process; do not inspect unrelated user PIDs. `createAgentCleanup` repeats this capability preflight before launch.
3. On EPERM/EACCES, unavailable native library, incomplete metadata or other failure, record `MAC_PROCESS_INSPECTION_UNAVAILABLE` and stop before dynamic tests. `kill(pid, 0)` and readable markers are insufficient. A sandbox allowing `ps` is also insufficient unless the actual native APIs work. Evaluate an explicitly authorized isolated test account/environment with these read-only capabilities; do not disable SIP, relax system security or use unnecessary global privileges.
4. M6: Run `bootstrap.test.js` and `recoveryLifecycle.test.js` only after M2/M2.5. Cover cold/20 parallel ensure, SIGTERM/SIGKILL/recovery, slow entry, late ready, startup exit, failed assertion cleanup and blocked pre-marker children. Inspect every cleanup artifact and confirm no unresolved original generations or orphans. Preserve the first failure.
5. M7: Only after safe M6, run `npm run lint` and `npm run verify` with default concurrency in unique synthetic HOME/XDG/cache/temp roots. Preserve retained fixtures instead of bulk deletion. Keep the two README failures distinct from new failures.

Windows mock success is `CROSS_PLATFORM_MOCK_CONTRACT_PASS`, never native Mac/Linux acceptance. Historical Archive/recovery/Fetch evidence gaps remain open; no test readiness timeout or production behavior is relaxed here.
